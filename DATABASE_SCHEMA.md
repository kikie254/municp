# DATABASE SCHEMA

Provider: SQLite (`prisma/schema.prisma`) for development and offline work; PostgreSQL
(`prisma/schema.postgresql.prisma`) for production. Identical models in both files.
Migrations: `prisma/migrations/20260101000000_init/migration.sql` (committed, generated by
`prisma migrate diff`, applied in this session with `npx prisma migrate deploy`).

## Entity map

| Model | Purpose | Key fields | Relations |
|---|---|---|---|
| `User` | Administrative account | `email` unique, `passwordHash` (scrypt), `role`, `isActive`, `lastLoginAt` | sessions, passwordResets, auditLogs, authored/reviewed content, assignments, notes |
| `Session` | Server-side session | `tokenHash` unique (SHA-256 of cookie), `expiresAt`, `userAgent`, `ipHash` | → User (cascade delete) |
| `PasswordReset` | Single-use reset token | `tokenHash` unique, `expiresAt`, `usedAt` | → User (cascade) |
| `NewsArticle` | News and announcements | `slug` unique, `status`, `publishedAt`, `scheduledFor`, `archivedAt`, `summary`, `body`, SEO fields | author, reviewer |
| `ProjectRecord` | Municipal project | `slug` unique, `projectStatus`, `location`, `budget`, `startDate`, `completionDate`, `implementingAgency`, `status` | author, reviewer |
| `PublicNotice` | Time-bound notice | `slug` unique, `category`, `body`, `expiresAt`, `documentId`, `status` | author |
| `DocumentRecord` | Uploaded file | `title`, `category`, `fileName`, `storageKey`, `mimeType`, `sizeBytes`, `checksum`, `status` | uploadedBy |
| `Submission` | Citizen enquiry/feedback/complaint/suggestion | `reference` unique, `type`, `status` (6 states), `assignedToId`, `ipHash`, `consent`, `resolvedAt` | assignee, notes |
| `SubmissionNote` | Internal case note | `body`, `internal` (default true) | → Submission (cascade), author |
| `ParticipationOpportunity` | Consultation/meeting/survey | `slug` unique, `kind`, `opensAt`, `closesAt`, `instructions`, `status` | responses |
| `ParticipationResponse` | Citizen response | `reference` unique, `ward`, `organisation`, `response`, `consent` | → Opportunity (cascade) |
| `AuditLog` | Append-only administrative trail | `action`, `entityType`, `entityId`, `summary`, `actorEmail`, `ipHash` | actor (nullable) |
| `RateLimit` | Fixed-window counter | `key` unique, `count`, `windowStart` | — |
| `EmailOutbox` | Outbound notification record | `status` (NOT_CONFIGURED/QUEUED/SENT/FAILED), `attempts`, `error`, `sentAt` | — |
| `Setting` | Deployment-level key/value | `key` PK, `value` | — |

## Status vocabularies

* Content: `DRAFT → IN_REVIEW → APPROVED → PUBLISHED`, plus `ARCHIVED`. `reject` returns to `DRAFT`.
* Submissions: `RECEIVED → UNDER_REVIEW → ASSIGNED → IN_PROGRESS → RESOLVED → CLOSED`.
* Email: `QUEUED` (attempt pending) → `SENT` (provider accepted) or `FAILED`; `NOT_CONFIGURED` when no credentials exist.

## Constraints and data rules

* `User.email` unique; `slug`/`reference`/`tokenHash` unique — enforced by the database, not by application code alone.
* Cascade deletes on `Session`, `PasswordReset`, `SubmissionNote`, `ParticipationResponse`; content and audit rows are never cascade-deleted, so history survives.
* `Submission.consent` is written from a validated `literal(true)`; a submission cannot exist without recorded consent.
* `budget` is free text and defaults to "not published" when empty — the platform never computes or estimates a figure.
* `ipHash` stores a salted 32-hex-character digest. Raw addresses are never persisted.

## Provider switch (SQLite → PostgreSQL)

```bash
cp prisma/schema.postgresql.prisma prisma/schema.prisma
# point DATABASE_URL at Postgres, then create the first migration for that provider:
npx prisma migrate dev --name init_postgres
npx prisma generate && npm run db:seed
```

The SQLite migration folder is provider-specific; do not apply it to Postgres. Regenerate it against the
target provider once, then keep using `prisma migrate deploy` in every later deployment.

## Backup and recovery

```bash
# SQLite
sqlite3 var/data/app.db ".backup '/backups/app-$(date +%F).db'"

# PostgreSQL
pg_dump "$DATABASE_URL" --format=custom --file="/backups/iten-tambach-$(date +%F).dump"

# Uploaded documents
tar czf "/backups/uploads-$(date +%F).tar.gz" var/uploads
```

Restore into a clean environment, then run `npm run db:migrate && npm start`. Verify with
`curl -s /api/health` (expect `200` and `"database":"ok"`) and by signing in to `/admin`.
Retention: submissions and participation responses are personal data — the retention period must be
approved by the Municipality (see `MUNICIPAL_APPROVAL_CHECKLIST.md`) before any purge job is scheduled.
